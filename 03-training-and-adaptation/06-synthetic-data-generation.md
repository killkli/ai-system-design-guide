## 「資料牆」之後：合成轉移

前沿模型（Llama 4、GPT-4o、Claude 4、Gemini 3.1 Pro）的訓練資料規模達到 15T 至 100T token。在此規模下，**去重**與**品質過濾**是主要差異化因素。
**現實：** 前沿微調（及 10% 預訓練）的訓練混合中，超過 **50%** 現在是合成資料。

| 來源 | 人類資料 | 合成資料 |
|--------|------------|----------------|
| **數量** | 固定（有限） | 無限 |
| **品質** | 多變（嘈雜） | 可控（淨化） |
| **成本** | 高（人類標記者） | 便宜（推論/GPU） |
| **偏見** | 反映網路 | 可手動平衡 |

## Evol-Instruct 模式

Evol-Instruct 是一個遞迴過程，其中 LLM 獲取簡單指令並將其演化為更複雜的指令。

**演化方向：**
1. **廣度**：增加任務數量。
2. **深度**：新增約束、複雜因素或多步邏輯。
3. **去噪**：清理措辭以移除「AI 味」。

```python
# 簡單指令：「寫一個將兩個數字相加的函式。」
# 演化指令：「寫一個執行矩陣加法的執行緒安全 Python 類別，包含錯誤處理與單元測試，遵守 PEP8。」
```

## Constitutional AI 與 AI 回饋（RLAIF）

由 Anthropic 開發並被業界廣泛採用的 RLAIF，使用「章程（一組規則）」來引導模型評估和改進自己的資料。

**循環：**
1. **提議**：模型 A 生成回應。
2. **批評**：模型 B（章程裁判）根據指南識別缺陷。
3. **修訂**：模型 A 根據批評生成更好版本。
4. **訓練**：(提示、修訂) 最終配對被添加至 SFT 集。

## 可驗證合成資料

合成資料最大的風險是**模型崩潰**（模型從自身的錯誤中學習）。
**2025 年解決方案**：專注於無需 LLM 即可驗證「真相」的領域。

- **數學**：使用形式驗證（Lean/Isabelle）或 Python 執行來驗證答案。
- **代碼**：對測試案例運行生成的代碼（單元測試）。
- **RAG**：使用「黃金上下文」生成問題，其中答案明確在文字中。

## 去偏與多樣性

合成資料用於「填補」人類資料中的空白。
- **語言**：透過翻譯概念模板生成低資源語言（如斯瓦希里語、馬拉地語）的高品質文字。
- **邏輯**：創建 1,000,000 種特定邏輯謬誤的變體，以「強化」模型抵禦它們。

## 面試問題

### Q：在合成資料上訓練時，「模型崩潰」的風險是什麼？

**最佳答案：**

模型崩潰發生在模型在由早期版本自身生成的資料上訓練時。因為模型的分布比現實世界更窄（它對某些詞和模式有偏好/偏見），訓練循環成為錯誤和平淡的正反饋循環。到 2025 年，我們透過以下方式緩解：
1. 混合 5-20%「黃金」人類認證資料。
2. 使用「可驗證」獎勵（數學/代碼），錯誤永遠不會被學習。
3. 使用更強大的「教師」模型為「學生」模型生成資料。

### Q：如何確保 1000 萬行合成資料集的*品質*？

**最佳答案：**

我們使用**多階段過濾管線**：
1. **語義去重**：使用嵌入來移除近乎相同的叢集。
2. **LLM-as-Judge**：對 1% 資料進行採樣，並讓更強大的模型（如 GPT-4o、Claude 4）對其邏輯與安全性評分。
3. **困惑度過濾**：使用小型模型計算文字的困惑度。如果太高（胡言亂語）或太低（重複/簡單），則丟棄。
4. **可驗證執行**：如果資料包含代碼或數學，它必須通過本地編譯器/直譯器檢查。
